# Development Rules

## Architecture Freeze

После Architecture Freeze любое архитектурное изменение допускается только в том случае, если оно:

- устраняет критическую проблему; или
- значительно упрощает систему без нарушения существующих контрактов.

Изменения, нарушающие утвержденные контракты, границы слоев или зависимости AI Core, запрещены без отдельного согласования.

## Architecture Change Policy

Любое изменение Architecture Freeze допускается только при выполнении хотя бы одного из условий:

- обнаружено нарушение SOLID в существующем коде;
- появляется дублирование логики минимум в двух местах;
- новый функционал невозможно реализовать без изменения архитектуры;
- изменение уменьшает сложность системы без нарушения существующих контрактов.

Во всех остальных случаях архитектура остается неизменной.

## Component Creation

Новый компонент появляется только тогда, когда он решает существующую проблему, а не потенциальную будущую.

Запрещено добавлять компоненты, сервисы, слои или абстракции только ради гипотетического будущего расширения.

## Confirmed Data

В v2 все новые источники данных обязаны явно заполнять `confirmed_fields`.

Правила:

- пустой `confirmed_fields` не является подтверждением данных;
- наличие поля в объекте не означает, что поле подтверждено;
- AI Validator и проверки подтверждения используют только явный список `confirmed_fields`;
- каждый новый provider обязан заполнять `confirmed_fields` при маппинге в domain-модель;
- цена с Bitrix подтверждается только из `catalog.price.list` (`"price"` в `confirmed_fields`);
- если клиент спрашивает цену, а `"price"` не подтверждена — Validator → `NEEDS_DATA` → handoff менеджеру.

## Knowledge Search Responsibility

`KnowledgeSearchService` никогда не принимает решения, какой источник "лучше".

Он только возвращает кандидатов.

Выбор делает `SourceSelector`.

## Data Source Split (Bitrix vs Knowledge Base)

- Bitrix: товар, цена, наличие, характеристики.
- Knowledge Base: оплата, доставка, гарантия, компания, FAQ.
- Delivery / payment / warranty **не** хранятся и не читаются из Bitrix.

## Architecture Freeze v2.1

После Architecture Freeze v2.1 запрещены любые новые архитектурные изменения до появления реальной причины в коде.

Зафиксированные решения:

- Tool Registry на текущем этапе существует только как контракт.
- Для ошибок и аудита используется единый LoggingService вместо двух отдельных компонентов.
- Session Manager и Conversation Manager могут иметь одну MVP-реализацию ConversationStateService, но сохраняют два отдельных интерфейса.
- Decision Router остается максимально тонким и только маршрутизирует готовый ProcessingResult.
- Source Selector только выбирает источники и не выполняет AI-ranking, RAG, validation или бизнес-решения.

## Step Architecture Review

После каждого шага реализации необходимо проверить:

Есть ли в предложенной архитектуре нарушение принципа Single Responsibility или зависимость, которая может затруднить масштабирование проекта?

Если нарушение найдено, нужно предложить улучшение до начала следующей реализации.
