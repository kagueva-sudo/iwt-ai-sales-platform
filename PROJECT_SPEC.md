## 1. Цель проекта

Создать платформу **AI Sales** для IWT: автоматизация и усиление продаж с помощью ИИ — квалификация лидов, персонализация коммуникаций, рекомендации действий менеджерам и аналитика воронки.

## 2. Задачи

1. Единый кабинет продаж с ИИ-ассистентом по сделкам и клиентам.
2. Интеграция с CRM / каналами коммуникации (email, мессенджеры — по приоритету этапа).
3. Автоматическая квалификация и скоринг лидов.
4. Генерация черновиков писем/ответов и follow-up с контролем менеджера.
5. Дашборды: воронка, конверсия, нагрузка, эффект ИИ.
6. Роли, права доступа, аудит действий.

## 3. Целевые пользователи

| Роль | Описание |
|------|----------|
| Менеджер по продажам | Работа с лидами/сделками, ИИ-подсказки, черновики сообщений |
| Руководитель продаж | Воронка, KPI, контроль качества коммуникаций |
| Администратор | Пользователи, интеграции, настройки промптов/политик |
| Клиент (опционально) | Самообслуживание / портал — вне MVP, если не согласовано иначе |

## 4. Область работ (Scope)

### 4.1. Входит в MVP

- Авторизация и роли (менеджер, руководитель, админ).
- Карточки лидов/сделок: статус, история, заметки.
- ИИ-скоринг лида и краткое обоснование.
- ИИ-рекомендация следующего шага (next best action).
- Генерация черновика сообщения по контексту сделки (с ручным утверждением перед отправкой).
- Базовая аналитика воронки.
- Логирование запросов к ИИ и ключевых действий пользователей.

### 4.2. Не входит в MVP (бэклог)

- Полноценный call-center / телефония.
- Автоотправка сообщений без подтверждения менеджера.
- Мобильное нативное приложение.
- Сложный BI (произвольные кубы, экспорт в сторонние BI) — только базовые отчёты.
- Мультитенантность для внешних клиентов SaaS (если IWT — внутренний продукт).

## 5. Функциональные требования

### 5.1. Лиды и сделки

- CRUD лидов/сделок.
- Этапы воронки (настраиваемый список статусов).
- Фильтры, поиск, назначение ответственного.
- История изменений статуса и комментарии.

### 5.2. ИИ-ассистент

- Скоринг лида (балл + факторы).
- Саммари переписки/заметок по сделке.
- Рекомендация следующего действия.
- Черновик ответа/письма на выбранный тон и цель.
- Все ИИ-результаты помечаются как «предложение ИИ»; отправка только после approve менеджера.

### 5.3. Коммуникации

- Хранение треда сообщений по сделке (ручной ввод + импорт из интеграций на этапе 2).
- Шаблоны сообщений + ИИ-дополнение под клиента.

### 5.4. Аналитика

- Количество лидов по этапам.
- Конверсия этап → этап.
- Активность менеджеров.
- Доля сделок с использованием ИИ-рекомендаций (метрика adoption).

### 5.5. Администрирование

- Управление пользователями и ролями.
- Настройки интеграций (ключи, webhooks).
- Базовые политики ИИ (язык, тон, запрещённые темы/формулировки).

## 6. Нефункциональные требования

| Требование | Целевой уровень |
|------------|-----------------|
| Язык UI | Русский (основной); EN — опционально |
| Доступность | Web, desktop-first; адаптив для планшета |
| Производительность | Ответ API p95 &lt; 1 с (без ИИ); ИИ-ответ p95 &lt; 15 с |
| Доступность сервиса | 99% в рабочие часы (MVP) |
| Безопасность | HTTPS, RBAC, секреты вне репозитория, аудит |
| Хранение ПДн | Согласовать с политикой IWT (резидентность, сроки) |
| Наблюдаемость | Логи, метрики ошибок, трейсинг вызовов ИИ |

## 7. Интеграции (ориентир)

## 9. Данные и сущности (минимум)

- Lead / Deal, Stage, Activity

- AuditLog

## 10. UX-принципы

- ИИ — помощник, не автономный продавец в MVP.
- Один основной сценарий на экран: сделка → контекст → рекомендация → действие.
- Черновики ИИ всегда редактируемы до отправки.
- Понятная индикация: «сгенерировано ИИ», «утверждено менеджером».

## 11. Этапы поставки

| Этап | Содержание | Результат |
|------|------------|-----------|
| 0 | Уточнение CRM, ролей, воронки, LLM | Согласованный scope MVP |
| 1 | Auth, сделки, воронка, базовый UI | Рабочий кабинет без ИИ |
| 2 | ИИ: скоринг, next action, черновики | ИИ в контуре сделки |
| 3 | Аналитика + админка политик | Отчёты и контроль |
| 4 | Интеграции CRM/email | Синхронизация и отправка |

## 12. Критерии приёмки MVP

1. Менеджер создаёт/ведёт сделку по этапам воронки.
2. По сделке доступны скоринг и next best action от ИИ.
3. Черновик сообщения генерируется и редактируется; без approve отправки нет.
4. Руководитель видит воронку и базовые KPI.
5. Админ управляет пользователями; секреты не в коде.
6. Ключевые действия пишутся в audit log.

## 13. Риски

- Неопределённость CRM и качества входящих данных.
- Галлюцинации LLM → обязательный human-in-the-loop.
- Требования к ПДн и хранению переписок.
- Стоимость и лимиты LLM API.
